# 드리프트 보정 자동화 초안

- 작성일: 2026-09-18
- 상태: **초안 — 현상 미측정.** 아래 원인 분석은 코드 근거에 기반한 가설이고, 실측 전에는 어느 것이 지배적인지 알 수 없다.
- 대상 환경: `debris_capture_visual`, `env.robot=canadarm3`
- 목적: 포획 후 체결(peg-in-hole)까지의 자세 유지·보정을 자동화하고, 그 과정에서 학습 기반 모델이 정당화되는지 판단한다.

## 한 줄 결론

"가만히 있어도 중력으로 내려앉는다"는 전제는 이 환경에서 성립하지 않는다. 무중력이다. 실제로 남는 것은 **명령 래칭, 관절 컴플라이언스, 페이로드 모멘텀** 세 가지이며, 셋 중 무엇이 지배적인지를 30초짜리 측정 하나로 가른 뒤에 모델을 만들지 말지 정한다.

## 1. 전제 정정

### 1.1 중력은 0이다

`project/srb/core/domain.py:40-41`

```python
case Domain.ORBIT:
    return 0.0
```

`TaskCfg.domain = Domain.ORBIT`이므로 `sim.gravity`는 0으로 설정된다. 정지 상태의 질량은 힘을 만들지 않으므로 **중력에 의한 정상상태 처짐은 존재하지 않는다.** 중력 보상(gravity compensation)을 학습 목표로 잡으면 존재하지 않는 현상을 모델링하게 된다.

### 1.2 관절값 토픽은 이미 있다

`project/srb/interfaces/interface/ros.py:163-177`에서 `scene._articulations`의 모든 항목에 대해 조건 없이 발행한다. 노드 네임스페이스가 `srb`(`ros.py:86`)이므로 최종 토픽명은 다음과 같다.

```
/srb/env0/robot/joint_states
```

`position`, `velocity`, `effort`(= `applied_torque`)가 모두 채워져 나온다. 별도의 수집 코드 없이 학습 입력으로 쓸 수 있다.

```bash
ros2 topic list | grep joint
ros2 topic echo /srb/env0/robot/joint_states --once
```

## 2. 실제 드리프트 원인 후보

무중력·고정베이스 조건에서 남는 것은 셋이다. 우선순위는 발생 가능성 추정치이며, 측정 전에는 순서가 바뀔 수 있다.

### 2.1 IK 명령 래칭 (제어 문제, 모델링 대상 아님)

`differential_inverse_kinematics` 액션은 마지막으로 받은 twist를 계속 유지한다. `mep_suction_capture.py`의 `stop()`이 종료 시 zero twist를 publish하는 이유가 이것이다.

```python
def stop(self):
    # The IK action latches the last command -> leave the arm with a zero twist
```

**0이 아닌 twist가 남아 있으면 팔은 계속 움직인다.** 이것은 드리프트가 아니라 살아있는 명령이며, 측정 시 반드시 분리해야 한다. 측정 프로토콜에서 zero twist를 명시적으로 유지하는 이유다.

### 2.2 관절 드라이브 컴플라이언스

`project/srb/assets/robot/manipulation/canadarm3.py:64-75`

```python
effort_limit_sim=2500.0
velocity_limit_sim=5.0
stiffness=40000.0
damping=25000.0
```

implicit actuator는 스프링-댐퍼다. 정상상태에서 `토크 = stiffness × 위치오차`이므로, 관절에 걸리는 토크가 있으면 위치 오차가 남는다. 무중력이라 정지 시 정적 토크는 0에 가깝지만, **가속 중이거나 접촉이 있으면** 오차가 생긴다. 특히 peg가 노즐 내벽에 닿는 순간이 그렇다.

크기 추정: 관절 하나에 2500 N·m(포화)가 걸리면 위치 오차는 `2500 / 40000 = 0.0625 rad ≈ 3.6°`. peg 끝이 IK 제어점에서 약 11 m이므로 **최악의 경우 끝단에서 0.69 m**. 이것이 사실이면 체결 공차(약 0.30 m)를 훨씬 넘는다.

### 2.3 페이로드 모멘텀 (가장 유력)

MEP 질량은 `MassPropertiesCfg(mass=3000.0)`으로 3000 kg에 고정되어 있다(`task.py`). 무중력에서 3000 kg을 가속하면 멈추기 위해 같은 크기의 역충격이 필요하다. 팔이 명령을 끊는 순간 페이로드가 팔을 끌고 가며, 관절 스프링이 이를 되받아 **감쇠 진동**이 남는다.

이것이 우주로봇의 고전 문제이고, 위 셋 중 유일하게 "가만히 있는데 계속 보정한다"는 관찰과 직접 들어맞는다.

증폭 요인: 포획점에서 peg 끝까지 **10.19 m**다(마커 body 좌표 `(-1.5689, 7.0549, -0.079)`, peg 끝 `(-1.6457, -2.2142, 0.0965)`, 스폰 스케일 1.1). 플랜지에서 1°의 각도 오차가 끝단에서 0.18 m가 된다.

## 3. 측정 프로토콜

모델을 만들기 전에 현상의 크기를 잰다. 코드 작성 없이 기존 토픽만으로 가능하다.

### 3.1 실험 A — 정지 유지 드리프트

1. `mep_suction_capture.py`를 돌려 `HOLD` 상태까지 간다(흡착 완료).
2. zero twist를 유지한다(노드를 `phase2_enabled:=false`로 띄우거나 `HOLD`에서 정지).
3. 30초간 기록한다.

```bash
ros2 bag record -o drift_hold \
  /srb/env0/robot/joint_states /tf /tf_static /mep_suction_capture/state
```

측정량:

| 항목 | 계산 | 의미 |
|---|---|---|
| peg 끝 위치 드리프트 | `srb/env0/debris` TF + peg body 오프셋 `(-1.81027, -2.43562, 0.10615)` | 체결에 직접 영향 |
| 관절 위치 변화 | `joint_states.position` 시계열 | 컴플라이언스 여부 |
| 관절 속도 잔류 | `joint_states.velocity` | 모멘텀·진동 여부 |
| 관절 토크 | `joint_states.effort` | 포화(2500) 도달 여부 |

### 3.2 실험 B — 정착 특성

1. 0.05 m/s로 5초간 이동 명령을 준다.
2. zero twist로 끊는다.
3. 20초간 같은 항목을 기록한다.

측정량: 오버슈트, 정착 시간, 진동 주파수, 잔류 정상상태 오차.

### 3.3 실험 C — 자세 의존성

실험 B를 팔의 서로 다른 자세 5곳에서 반복한다. 잔류 오차가 자세에 따라 크게 달라지면 관성 행렬의 자세 의존성이 원인이고, **여기서부터 학습 모델이 정당화된다.**

## 4. 판단 기준

실험 A의 30초 peg 끝 드리프트를 기준으로 갈린다. 비교 대상은 체결 공차다 — 노즐 입구 반경 0.332 m, peg 끝 반경 0.033 m이므로 **횡방향 여유는 약 0.30 m**이고, 현재 스크립트의 정렬 공차는 `insert_lat_tol = 0.05 m`다.

| 드리프트 | 판단 | 조치 |
|---|---|---|
| < 10 mm | 무시 가능 | 아무것도 하지 않는다. 모델을 만들 이유가 없다. |
| 10 – 50 mm | 제어로 해결 | 임피던스 제어 또는 input shaping. ML보다 간단하고 방어하기 쉽다. |
| > 50 mm, 자세 무관 | 제어로 해결 | 위와 동일. 게인 재조정. |
| > 50 mm, **자세 의존** | 학습 정당화 | 잔류 동역학 회귀 모델 (5.2절) |

마지막 칸에 해당할 때만 학습을 쓴다. 그 전에 쓰면 고전 제어로 풀리는 문제에 모델을 얹은 것이 되어 오히려 약점이 된다.

## 5. 데이터 활용 방향 비교

| | 내용 | 라벨 확보 | 원천기술 어필 | 위험 |
|---|---|---|---|---|
| **A** | MEP 카메라 → 노즐 6-DoF 자세 회귀 CNN | 자동 (TF) | 높음 | 낮음 |
| **B** | 관절상태 + 명령 → 정착 오차 예측, 피드포워드 보정 | 자동 (TF) | 중간 | 중간 |
| **C** | 삽입 실패·끼임 예측 분류기 | 반자동 | 낮음 | 낮음 |

### 5.1 A — 학습 기반 노즐 자세 추정 (선행 추천)

현재 `VisualTaskCfg.thruster_ring_*`가 노즐 앞에 초록 고리를 만들고, `vision_servo.fit_circle_3d`가 그것을 기하학적으로 피팅한다. 동작하지만 **"피듀셜 마커를 붙여 푼 것"이라는 지적을 받는 구조**다.

CNN으로 대체하면 고리를 제거할 수 있고, 그 서사 자체가 어필 포인트가 된다.

- 입력: `cam_mep` RGB(+D), 320×240
- 출력: 노즐 중심 3D + 축 방향 (또는 이미지 상 중심 + 깊이 + 법선)
- 라벨: `srb/env0/satellite` TF + 노즐 asset 오프셋 `(-0.05, -2.721, -0.01)` × 스케일 2.0 → **모든 프레임에 정확한 정답이 공짜로 붙는다**
- 베이스라인: 현재의 원 피팅 (이미 있음, 성능 비교 대상으로 그대로 사용)
- 규모 추정: 1~5만 프레임, ResNet-18 이하, 기존 GPU로 30분 내외

도메인 랜덤화 재료는 이미 환경에 있다: 위성 자세, 스카이돔 방향(`events.randomize_skydome_orientation` — 현재 의도적으로 비활성), 조명.

### 5.2 B — 잔류 동역학 회귀

4절의 판단 기준을 통과했을 때만 착수한다.

- 입력: 관절 위치·속도·토크 (7×3), 명령 twist (6), 페이로드 부착 여부/질량
- 출력: N초 후 peg 끝 자세 오차 (6)
- 용도: 피드포워드 보정항으로 `_insert_servo`에 더한다
- 모델: MLP 2~3층이면 충분하다. 딥러닝이라 부를 규모가 아니고, 그게 맞다.

### 5.3 C — 삽입 결과 분류

최근 N스텝의 토크·속도 시계열로 끼임을 조기 판정한다. 데모로는 좋으나 원천기술로 내세우기엔 약하다.

## 7. 열린 질문

- 실험 A에서 관절 토크가 2500에 포화하는가? 포화한다면 원인은 컴플라이언스이고, 액추에이터 파라미터 재조정이 먼저다.
- 위성을 자유 부유 상태로 두면(현재는 정지) 목표가 움직인다. 드리프트 측정은 목표 정지 조건에서 먼저 한다.
- 위성 질량이 밀도 3000 kg/m³ 기준 약 10⁶ kg로 추정된다. 자유 부유 실험을 하려면 MEP처럼 질량을 직접 지정해야 한다.
- 데이터 규모: bag으로 몇 회 실행분이 필요한지는 A안 착수 후 학습 곡선을 보고 정한다.
