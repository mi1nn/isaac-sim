## 수정 내용

### 1. ROS 2 bridge 초기화

`project/srb/utils/ros.py`

- 설치된 `jazzy`, `humble` 번들을 탐색하고 사용 가능한 distro를 선택한다.
- `<bridge>/<distro>/rclpy`를 `sys.path`에 추가한다.
- native library 경로와 `ROS_DISTRO`, `RMW_IMPLEMENTATION`을 설정한 뒤 bridge를 활성화한다.
- `require_ros2_bridge()`를 추가했다. 초기화가 실패하면 이후 `import rclpy`까지 진행하지 않고 `RuntimeError`로 즉시 중단한다.

`project/srb/__main__.py`, `project/srb/interfaces/interface/ros.py`

- `enable_ros2_bridge()` 직접 호출을 `require_ros2_bridge()`로 교체했다.
- 실패 위치와 원인이 startup 단계에서 바로 드러나도록 했다.

### 2. TF broadcaster fallback

`project/srb/utils/ros.py`, `project/srb/interfaces/interface/ros.py`

- 실제 `tf2_ros`가 있으면 기존 broadcaster를 사용한다.
- 없으면 `tf2_msgs/TFMessage`를 `/tf`, `/tf_static`에 직접 발행한다.
- static transform은 `(parent, child)` 쌍별 최신 값을 보관하고 transient-local QoS로 재발행한다.

`project/srb/tasks/manipulation/debris_capture/task.py`

### 8. 동작 속도

`_publish_command` 가 `lin = v / ik_lin_gain` 후 `max_action` 으로 clamp 하므로,
실제 속도 상한은 `ik_lin_gain × max_action` = `0.17 × 1.0` = **0.17 m/s** 였다.
`max_lin_vel` 만 올려서는 액션이 포화돼 효과가 없다.

액션이 시뮬레이터로 가는 경로 어디에서도 clip 되지 않는 것을 확인했다. env 는
`Box(-1, 1)` 을 선언하지만 ROS 인터페이스도 `_pre_physics_step` 도 강제하지 않으며,
실제 backstop 은 팔의 `velocity_limit_sim = 5 rad/s` 다.

| 파라미터 | 이전 | 이후 |
|---|---|---|
| `max_action` | 1.0 | 3.0 (상한 0.17 → 0.51 m/s) |
| `max_lin_vel` / `max_rot_vel` | 0.12 | 0.36 |
| `search_max_rot_vel` | 0.15 | 0.45 (360° 스윕 42초 → 14초) |
| `dock_lin_vel` | 0.04 | 0.12 |
| `kp_lin` / `kp_rot` | 0.6 / 0.8 | 1.2 / 1.6 |
| `control_rate` | 20 Hz | 30 Hz |
| `estimate_smoothing` | 0.3 | 0.5 |
| `standoff` | 0.8 m | 0.6 m |

`dock_lin_vel` 은 상한의 24% 로 유지했다. 접촉으로 끝나는 구간이고 MEP 가 무거워
빠르게 밀면 튕겨나간다.

### 9. 물리 연산 CPU 강제 (미검증)

`project/srb/core/env/common/base/env_cfg.py`

```python
def _ensure_cuda_sim_device_for_deformable_objects(self):
    for asset_cfg in self.scene.__dict__.values():
        if isinstance(asset_cfg, DeformableObjectCfg):
            self.sim.device = "cuda"
            break
    else:
        self.sim.device = "cpu"     # 변형체가 없으면 무조건 CPU
```

함수명과 달리 `else` 가 변형체 없는 모든 씬을 CPU 로 강제한다. 이 프로젝트 씬에는
변형체가 없다. 또한 이 함수는 `__post_init__` 마지막(`env_cfg.py:194`)에서 호출되어
Hydra 오버라이드보다 나중에 실행되므로, `env.sim.device=cuda` 를 줘도 덮어썼다.

`env_cfg.py:104` 주석은 "`__main__.py` 에서 GPU 로 바꿈"이라고 되어 있으나 해당 코드는
저장소에 존재하지 않는다. 주석이 코드보다 오래된 상태였다.

`else` 분기를 제거해 변형체가 있을 때만 CUDA 로 올리고, 없으면 설정값을 존중하도록 했다.

```bash
srb agent ros ... env.robot=canadarm3 env.sim.device=cuda
```

기본값은 CPU 로 유지했다. `CaptureManager._attach()` 가 시뮬레이션 실행 중에
`UsdPhysics.FixedJoint` 를 생성하는데, GPU 파이프라인에서는 물리 뷰가 시작 시점에
고정되어 런타임 조인트가 반영되지 않을 수 있다. **GPU 전환 시 흡착이 동작하는지 먼저
확인해야 한다.**

참고로 GPU 연결 자체는 정상이다. `nvidia-smi` 에서 Isaac Sim 프로세스가 2861 MiB 를
`C+G` 타입으로 사용 중이다. 다만 전력 상한이 `58W / 80W`, 온도 79°C 로 낮게 잡혀 있어
노트북 전원 프로파일 확인이 필요하다.
