# 위성 임무 연장 시스템 개발 우선순위 및 작업 순서

> 기준일: 2026-09-17  
> 기준 요구사항: `docs/md/요구사항_정리.md` v1.0  
> 대상 저장소: Space Robotics Bench(SRB) 기반 수정 코드
> 최신 실행 결과: **12절**. 3절의 코드 분석은 P0 구현 전 상태를 기록한 것이다.

## 1. 이 문서의 목적

이 문서는 요구사항과 현재 코드베이스를 대조하여 다음 내용을 한곳에 유지한다.

- 전체 시스템이 어떤 순서로 동작하는지
- 현재 구현된 부분과 아직 구현되지 않은 부분
- 1차 시연을 위해 무엇부터 개발해야 하는지
- 각 작업의 완료 조건과 다음 작업으로 넘어가는 기준
- 기존 SRB 코드에서 재사용할 부분과 새로 만들 부분

현재 최우선 목표는 **유영 중인 MEP의 GT 파지점을 계속 갱신하면서 Canadarm3가 접근해 Kinova 그리퍼로 한 번 이상 파지하는 것**이다. SAM2, LLM, 도킹 전체 통합은 이 동작이 확보된 뒤 진행한다.

## 2. 전체 시스템 동작 흐름

```text
[INIT]
  씬·로봇·MEP·위성 로드
      ↓
[MOTION]
  MRV 공통 궤도 표현 + MEP 상대 유영 δ(t)
      ↓
[TRACK]
  GT 스텁 또는 비전이 /mep/grasp_pose 발행
      ↓
[APPROACH]
  최신 pose 필터링·예측 → Canadarm3 IK 목표 갱신
      ↓
[GRASP]
  허용 오차 진입 → Kinova 폐합 → 파지 성공 판정
      ↓
[ATTACH]
  그리퍼–MEP FixedJoint 생성, T_E_M 고정
      ↓
[ALIGN]
  MEP 카메라로 LAE 도킹점 추정 → 프로브 축 정렬
      ↓
[INSERT]
  저속 삽입 → 깊이·접촉 상태로 성공 판정
      ↓
[DONE] 또는 [ABORT]
```

### 단계별 데이터 흐름

| 단계 | 입력 | 처리 | 출력 |
| --- | --- | --- | --- |
| 환경 | YAML 파라미터, USD 에셋 | 씬과 물리 속성 초기화 | MRV, MEP, 위성, 카메라 |
| 모션 | 시간, 궤도 반경·각속도, 유영 seed | 공통 궤도와 MEP 상대 유영 계산 | MRV·MEP pose |
| 파지점 | GT 프레임 또는 RGB-D·마스크 | `mrv/base_link` 기준 6D pose 계산 | `/mep/grasp_pose` |
| 파지 제어 | 최신 grasp pose, TCP pose | 필터·stale 검사·IK·그리퍼 제어 | 팔/그리퍼 action |
| 부착·도킹 | 파지 상태, dock point | FixedJoint, 정렬, 삽입 | DONE/ABORT 및 로그 |

### 3.4 현재 `debris_capture`를 그대로 확장하면 생기는 문제

- `TaskCfg`가 `ManipulationEnvCfg`를 사용하므로 현재 로봇은 기본 Franka다.
- MEP와 위성을 추가로 스폰하지만 기존 `debris`가 관측·보상·접촉 필터의 실제 대상이다.
- `Kinova300Large`가 Canadarm3의 `end_effector`로 지정되지 않았다.
- 임무 전용 로직을 기존 오픈소스 태스크에 계속 추가하면 upstream 코드와 프로젝트 코드의 경계가 사라진다.
- 따라서 기존 코드는 참고만 하고 `satellite_mission` 전용 태스크로 분리하는 것이 안전하다.

## 4. 우선순위

### P0. 전용 태스크와 기본 씬 완성

**예상 시간: 3~5시간**

작업:

1. `srb/tasks/manipulation/satellite_mission/`을 만든다.
2. `Canadarm3(end_effector=Kinova300Large())` 조합을 태스크 기본 로봇으로 지정한다.
3. MEP와 위성을 전용 `SceneCfg`에 등록하고 기존 `debris` 의존성을 제거한다.
4. USD 필수 prim과 물리 속성을 시작 시 검증한다.
5. zero/teleop 실행으로 씬 로드와 그리퍼 개폐를 확인한다.

완료 조건:

- Canadarm3, 확대 Kinova, MEP, 위성이 오류 없이 한 씬에 나타난다.
- 확대 Kinova가 Canadarm3 플랜지에 붙어 있다.
- 그리퍼 open/close action이 동작하며 떨림·관통이 없다.
- MEP가 하나의 rigid body로 움직이고 collision이 동작한다.

### P1. 결정론적 MEP 유영과 GT 인터페이스

**예상 시간: 3~4시간**

작업:

1. 유영 파라미터 YAML에 진폭, 주기, 위상, seed를 정의한다.
2. MEP pose를 `orbit_ref + δ(t)`로 매 물리 스텝 갱신한다.
3. `mep/grasp_frame`의 world pose를 `mrv/base_link` 기준 pose로 변환한다.
4. GT 스텁에서 `/mep/grasp_pose`를 10Hz 이상 발행한다.
5. pose timestamp와 source(`gt`/`vision`)를 로그에 남긴다.

완료 조건:

- 같은 seed로 두 번 실행했을 때 MEP 궤적이 같다.
- `/mep/grasp_pose`가 정해진 frame과 timestamp로 연속 발행된다.
- MEP 유영을 중지하지 않고 pose를 시각화할 수 있다.

### P2. 실시간 보정 접근과 파지

**예상 시간: 4~8시간**

작업:

1. grasp pose subscriber와 최신 pose buffer를 만든다.
2. 저역통과 필터, pose age 검사, 짧은 선형 예측을 적용한다.
3. pre-grasp → approach → close 상태를 구현한다.
4. TCP 오차와 상대 속도로 폐합 시점을 결정한다.
5. 실패하면 그리퍼를 열고 후퇴한 뒤 재접근한다.

완료 조건:

- pose가 끊기거나 stale이면 팔이 접근을 멈춘다.
- 유영 MEP에 대해 목표 pose가 계속 갱신된다.
- GT pose 기준으로 MEP를 한 번 이상 안정적으로 파지한다.
- 파지 직전 TCP 위치 오차와 pose age가 기록된다.

### P3. 1차 시연 안정화와 독립 검증

**예상 시간: 4~6시간**

작업:

1. 유영 진폭을 작은 값부터 올리며 성공 조건을 찾는다.
2. 파지 성공 장면을 녹화하고 재현용 YAML을 저장한다.
3. SAM2는 손목 카메라 녹화 프레임으로 독립 검증한다.
4. 기존 peg-in-hole 태스크를 기반으로 고정 hole 삽입을 독립 검증한다.
5. 시연 실행 명령과 실패 시 대체 절차를 문서화한다.

완료 조건:

- 라이브 시연용 파라미터와 녹화본이 있다.
- GT 파지 통합 동작과 SAM2·peg-in-hole 단독 결과를 각각 제시할 수 있다.

### P4. 2차 통합

**예상 시간: 3~6개 작업일**

작업 범위:

- 파지 성공 시 그리퍼–MEP FixedJoint 생성
- SAM2 tracking과 이벤트 기반 LLM 필터 연결
- MEP 카메라 기반 `/satellite/dock_point` 발행
- ALIGN/INSERT 재시도 제어와 임무 상태 머신
- rosbag 기록 및 성공률 반복 실험

## 5. 권장 구현 순서

```text
Gate 1: 정적 씬 로드
  T-01 USD 로드 → T-02 그리퍼 개폐
        ↓
Gate 2: 동적 목표 생성
  T-03 MEP 유영 → GT grasp pose 발행
        ↓
Gate 3: Critical Point
  T-04 pose 구독 → IK 접근 → 파지
        ↓
Gate 4: 1차 시연
  파라미터 고정 → 녹화 → 리허설
        ↓
Gate 5: 2차 기능
  SAM2/LLM → FixedJoint → 도킹 → 상태 머신
```

각 Gate가 통과되기 전에는 다음 Gate 기능을 통합하지 않는다. 특히 SAM2와 LLM을 먼저 붙이면 물리·제어 문제와 인지 문제를 구분할 수 없다.

## 7. 좌표계와 인터페이스 규칙

### 좌표계

- Isaac Sim 월드는 m 단위, Z-up을 유지한다.
- Phase 1 제어 명령은 `mrv/base_link` 기준으로 통일한다.
- MEP GT 프레임은 `mep/grasp_frame`, 프로브는 `mep/probe_tip`을 사용한다.
- 위성 도킹 기준은 `sat/lae_dock`을 사용한다.
- quaternion 순서는 SRB/Isaac Lab이 사용하는 순서를 코드 경계마다 명시한다.

### ROS 2

문서의 토픽명은 목표 인터페이스다. 실제 SRB bridge 토픽은 `/srb/env0/...` namespace를 사용하므로 처음 실행할 때 `ros2 topic list`로 매핑을 확정한다.

1차 필수 인터페이스:

| 이름 | 타입 | 규칙 |
| --- | --- | --- |
| `/mep/grasp_pose` | `geometry_msgs/PoseStamped` | frame은 `mrv/base_link`, 10Hz 이상 |
| 팔 action | SRB action mapping | 최신 pose를 기다리지 않고 주기적으로 적용 |
| 그리퍼 event | SRB binary action | pre-grasp 오차 조건 충족 시 close |
| `/clock`, `/tf` | ROS 표준 타입 | 모든 지연 계산은 simulation timestamp 사용 |

## 8. 핵심 기술 결정

### 8.1 1차는 고정 베이스 IK를 유지한다

`OrbitalManipulationEnvCfg`는 free-floating manipulator에서 Jacobian 기반 IK를 지원하지 않아 IK action을 joint-relative action으로 바꾼다. 1차 Critical Point는 pose 기반 추종이므로 다음 방식을 사용한다.

- 로봇팔 물리는 고정 베이스 `ManipulationEnv`에 둔다.
- 공통 궤도 성분은 배경·카메라·시각 기준점으로 표현한다.
- 제어 난이도에 직접 영향을 주는 MRV–MEP 상대 유영 `δ(t)`를 물리에 적용한다.
- 1차 성공 후 실제 orbital mobile base 적용을 별도 실험한다.

이 결정은 요구사항의 R-01 대체안과 일치한다.

### 8.2 GT와 비전은 같은 출력 계약을 사용한다

GT publisher와 vision publisher는 모두 동일한 `/mep/grasp_pose` 계약을 지켜야 한다. 파지 제어기는 source를 몰라도 동작해야 한다. 이 구조가 확보되면 2차에서 publisher만 SAM2 기반으로 교체할 수 있다.

### 8.3 에셋 검증을 제어 개발보다 먼저 한다

다음 prim과 물리 속성은 Isaac Sim stage에서 직접 검증한다.

- `mep/grasp_frame`, `mep/probe_tip`, `mep/dock_cam`
- `sat/lae_dock`
- MEP root RigidBody, collision mesh, mass/inertia
- LAE 노즐의 실제 빈 공간과 collision approximation
- Kinova 접촉 센서, joint limit, TCP offset

USD가 crate 형식이므로 일반 텍스트 검색만으로 prim 존재 여부를 확정할 수 없다.

## 10. 현재 주의사항

1. 기존 `debris_capture`에 임무 코드를 더 넣지 않는다. 신규 태스크로 분리한 뒤 현재 커스텀 스폰 코드를 이동한다.
2. `Kinova300Large`의 stiffness·damping·effort 값은 계산 근거보다 실행 안정성 검증이 먼저 필요하다.
3. MEP와 위성 초기 pose는 수동 배치 값이다. 전용 태스크에서는 로봇 base 기준 상대 pose로 다시 정의한다.
4. 문서의 `!flowchart.png`, `!architecture.png`는 실제 Markdown 이미지 링크가 아니며 해당 이미지 파일도 없다.
5. 저장소의 기존 테스트는 CLI/import 위주다. Isaac Sim 실행 검증은 별도 smoke test와 녹화가 필요하다.

## 12. P0 전용 태스크 및 속도 개선 실행 기록 (2026-09-17)

### 구현 결과

- `satellite_mission`, `satellite_mission_visual` 등록. 고정형 `ManipulationEnv`와
  `Canadarm3(end_effector=Kinova300Large())`를 기본값으로 사용한다.
- 프로젝트 태스크는 `debris_capture`를 상속하거나 기존 `debris`를 스폰하지 않는다.
  MEP, 위성, 팔, 그리퍼만 스폰한다. 초기 유영·관절 랜덤화를 끄고 자동 시간 종료도 끈다.
- `space_asset/mep.usd`를 상대경로로 참조하는 전용 USDA와 스폰 함수를 추가했다.
  원본 `space_asset/`은 수정하지 않았다. `pxr` stage traversal로 확인한 손잡이
  `gripper_fixture/Cylinder_01`의 중심을 MEP root로 옮겼다.
  원본 손잡이 중심 오프셋은 `(50.428281, 22.474291, 0.044022) m`였다.
- MEP root는 단일 동적 rigid body, 질량 100 kg이며 52개 형상에 collision을 적용한다.
  mesh에는 `convexDecomposition`을 사용한다. 손잡이 중심 초기 위치는
  env/world 기준 `(1.5, 3.5, 5.0) m`, quaternion은 **wxyz** `(0, 0, 0, 1)`이다.
  위성은 `(15, 12, 0) m`의 kinematic body로 배치한다.
- 그리퍼–MEP 접촉 센서를 명시적으로 만든다. 기존 공통 센서 패치에서 빠진
  `force_matrix_w_history` 버퍼를 보완해 현재 Isaac Lab의 reset 오류를 수정했다.
  필터 경로도 env 0에 고정되지 않게 수정했다.

### 속도 변경과 재현 조건

전용 `TaskCfg`의 `arm_damping` 기본값을 기존 25000에서 **5000**으로 낮췄다.
팔의 물리 속도 상한은 `arm_velocity_limit=0.5 rad/s`, IK 입력 scale은
`ik_action_scale=0.1`이다. 기존 Canadarm3 에셋과 다른 태스크의 기본값은 유지한다.

원인 확인을 위해 같은 씬·시작 자세·IK 입력 `x=0.2`·시뮬레이션 2초에서
감쇠값만 비교했다. TCP x방향 평균 속도는 **0.027484 → 0.077896 m/s (2.83배)**였다.
이는 해당 초기 자세와 입력의 시뮬레이션 측정값이며 모든 자세의 속도 보장은 아니다.

```bash
# 빠르게 움직이는 새 태스크 실행. 뷰포트를 클릭한 뒤 키보드 입력.
srb agent teleop --env satellite_mission env.num_envs=1 env.debug_vis=true

# 손목 RGB-D 및 전체 씬 카메라 포함. 디버그 마커가 영상에 보이면 false로 실행.
srb agent teleop --env satellite_mission_visual env.num_envs=1 env.debug_vis=false

# 감쇠값을 기존 응답으로 되돌려 비교할 때
srb agent teleop --env satellite_mission env.arm_damping=25000
```

기존 키보드 `P`는 입력 gain ×1.25, `O`는 ×0.75, `R`은 그리퍼 토글,
`L`은 씬 리셋이다. ROS pose 기반 제어의 입력 단위는 변경하지 않았다.
