# Part I. 비즈니스 요구서

## 1. 비즈니스 배경 및 문제 정의

### 1.1 시장 배경

- **로봇팔 기반 위성 수명 연장 서비스의 실운용 개시:** Northrop Grumman(SpaceLogistics)의 MRV(Mission Robotic Vehicle)가 MEP(Mission Extension Pod) 3기와 함께 2026년 7월 Falcon 9으로 발사되었다. MRV는 로봇팔 2기를 탑재하고, 연료가 떨어져 가는 고객 위성에 MEP를 부착해 추가 추진력을 제공하는 방식으로 위성 수명을 연장한다. 정지궤도 도달 후 실제 MEP 설치 작업이 시작될 예정이다.
- **서비스 방식의 전환:** 이전 세대 MEV는 서비싱 위성 자체가 고객 위성에 도킹해 함께 머무는 방식이었다. MRV-MEP 방식은 로봇팔이 소형 추진 모듈(MEP)을 설치하고 떠나기 때문에 한 대의 서비서가 여러 위성을 서비스할 수 있다. 그만큼 **"로봇팔로 모듈을 잡고, 옮기고, 정확히 꽂는" 조작 기술**이 사업의 핵심 역량이 된다.

### 1.2 문제 정의

| 구분 | 문제 | 영향 |
| --- | --- | --- |
| P1. 움직이는 파지 대상 | MRV와 MEP가 모두 궤도 운동 중이고, MEP는 3차원 공간에서 미세하게 유영한다. 고정 좌표 목표를 한 번 계산해 잡는 방식은 접근하는 동안 목표가 이미 이동해 실패한다 | 파지 실패, MEP를 밀어내는 2차 충돌 |
| P2. 파지 후 자세 오차 누적 | 그리퍼와 MEP 사이에 미끄러짐(roll·pitch·yaw 회전)이 생기면 프로브 축 정렬이 틀어진다 | peg-in-hole 도킹 실패, 노즐 손상 위험 |
| P3. 비협력 대상 인식 | 수명이 다한 기존 위성은 서비싱 전용 마커나 인터페이스가 없다. 도킹점(LAE 노즐)을 영상으로 직접 찾아야 한다 | 도킹점 인식 오류 시 임무 전체 실패 |
| P4. 실증 기회의 부재 | 궤도상 실험은 비용이 매우 크고 반복이 불가능하다 | 알고리즘은 발사 전에 가상 환경에서 반복 검증되어야 한다 |

### 1.3 디지털 트윈 접근의 필요성

실제 로봇과 궤도 환경을 사용할 수 없으므로, 물리 시뮬레이터에서 궤도 운동·유영·접촉을 재현하고 인지–제어 파이프라인을 조건을 바꿔가며 반복 실험한다. 여기서 확보한 **"움직이는 베이스에서 움직이는 대상을 잡고, 잡은 물체를 기준으로 도킹하는" 기술**은 궤도 서비싱뿐 아니라 이동형 매니퓰레이터 전반에 재사용할 수 있다.

## 2. 비즈니스 목표 및 핵심 성과 지표

**목표**

- 유영하는 모듈을 운용자 수동 지정 없이 자동 인식·추종·파지하는 파이프라인을 확보한다.
- 파지한 모듈을 기준 좌표로 삼아 비협력 위성의 도킹점에 정밀 도킹하는 절차를 검증한다.
- 조건(유영 진폭·주기, 초기 위치)을 바꾼 반복 실험으로 성공률과 한계 조건을 정량화한다.

**KPI (초안 — 1차 측정값을 보고 확정)**

| 지표 | 목표(초안) | 측정 조건 |
| --- | --- | --- |
| 유영 MEP 파지 성공률 | 80% 이상 | 동일 유영 조건에서 20회 시도, 초기 위치 랜덤 |
| 파지 직전 추종 오차 | 파지부 폭의 20% 이내 | 그리퍼 TCP–파지점 거리, 폐합 명령 시점 기준 |
| 파지점 발행 주기 | 10 Hz 이상 | Isaac Sim과 SAM2 동시 구동 상태 |
| 대상 식별 정확도 (LLM 필터) | 90% 이상 | 손목 카메라 프레임 세트에서 정답 마스크 선택 비율 |

# Part II. 시스템 요구서

## 1. 시스템 개요

### 1.1 시나리오

**Phase 1 — MRV 로봇팔의 MEP 파지**

1. MRV는 위성 궤도를 따라 이동한다 (베이스 좌표계 자체가 움직임).
2. MEP도 같은 궤도로 움직이되, 3차원 공간의 유영 움직임(xyz 방향 작은 떨림)을 가진다.
3. 로봇팔 손목 카메라 영상에 SAM2 세그멘테이션을 적용해 마스크를 만들고, LLM(VLM) API로 MEP 파지부 마스크를 확정한다.
4. 마스크의 최적점을 3D 파지점으로 바꿔 토픽으로 계속 발행하고, 로봇팔 제어기가 이를 구독해 파지점을 실시간으로 수정하며 접근·파지한다.

**Phase 2 — MEP 기준 프로브 도킹**

1. 파지 후 MRV 그리퍼와 MEP를 하나의 물체로 고정한다.
2. 프로브를 움직이는 구동부는 여전히 로봇팔이지만, 그리퍼–MEP가 고정되어 있어 둘 사이의 roll·pitch·yaw 미끄러짐 위험이 사라진다.
3. MEP에 달린 카메라로 LAE 도킹점을 인식한다 (마스킹 지점).
4. 프로브를 도킹점에 peg-in-hole 방식으로 삽입한다.

### 1.2 좌표계 정의

| 기호 | 프레임 | 설명 |
| --- | --- | --- |
| `W` | world | Isaac Sim 월드 좌표 (단위 m, Z-up) |
| `O` | orbit_ref | 축척 원궤도 위를 이동하는 기준점. MRV·MEP 공통 궤도 |
| `B` | mrv/base_link | MRV 로봇팔 베이스. **Phase 1 제어 기준** |
| `E` | mrv/tcp | 그리퍼 TCP |
| `Cw` | mrv/wrist_cam | 손목 RGB-D 카메라 광학 프레임 |
| `M` | mep/base | MEP 본체 |
| `G` | mep/grasp_frame | MEP 파지부 기준 프레임 (검증용 GT) |
| `P` | mep/probe_tip | 프로브 끝단. **Phase 2 제어 기준** |
| `Cm` | mep/dock_cam | MEP 도킹 카메라 광학 프레임 |
| `S` | sat/base | 수명 다한 위성 본체 |
| `D` | sat/lae_dock | LAE 노즐 도킹점 (노즐 축 위, 입구 중심) |

### 1.3 좌표 변환 체인

표기: `T_A_B` = A 프레임에서 본 B 프레임의 포즈.

**Phase 1 (파지점 발행)**

- MEP 운동: `p_M(t) = p_O(t) + δ(t)`, `δ(t)`는 xyz 각 축의 작은 떨림
- MRV 기준에서 보면 궤도 성분은 대부분 상쇄되고 `δ(t)`와 인지 지연이 제어 난이도를 결정한다
- 발행할 파지점: `T_B_grasp(t) = T_B_Cw(t) · T_Cw_grasp(t)` (`T_Cw_grasp`는 마스크 최적점 + depth로 계산)

**Phase 2 (도킹)**

- 고정 시점에 `T_E_M`이 상수가 되므로 `T_E_P = T_E_M · T_M_P`도 상수
- 도킹점 측정: `T_P_D = T_P_Cm · T_Cm_D` (`T_P_Cm`은 MEP 설계값 상수)
- 목표 프로브 포즈: `T_B_P* = T_B_P · T_P_D · T_D_P,des` (standoff 또는 삽입 깊이)
- 로봇팔 목표: `T_B_E* = T_B_P* · inverse(T_E_P)`

즉 Phase 2의 목표는 MEP(프로브) 프레임에서 정의되고, 로봇팔은 고정된 `T_E_P`를 통해 이를 자기 TCP 명령으로 바꿔 움직인다.

## 5. 시스템 Flow Chart

!flowchart.png

**범례:** 빨간 실선 = 1차 시연 Critical Point(통합 동작) · 주황 점선 = 1차 단독 검증(통합은 2차) · 파란색 = 2차 개발

### 5.1 흐름 설명

- **Phase 0 (A1~A5):** SRB 궤도 환경을 로드하고 MRV·MEP·위성 에셋을 스폰한다. MRV는 궤도를 따라 이동하고, MEP는 같은 궤도에 떨림을 더해 움직인다. 손목 카메라 스트림이 발행되면 Phase 1로 넘어간다.
- **Phase 1 (B1~B6):** SAM2 후보 마스크 → LLM으로 파지부 확정 → 최적점 + depth로 3D 파지점 계산 → 토픽 연속 발행 → 로봇팔이 구독해 보정 접근. 오차가 허용 범위에 들어올 때까지 보정을 반복하고, 폐합 후 성공하면 Phase 2로, 실패하면 개방·후퇴 후 다시 접근한다.
- **Phase 2 (C1~C6):** 그리퍼–MEP 고정 → 제어 기준을 MEP(프로브) 프레임으로 전환 → MEP 카메라로 LAE 도킹점 인식·발행 → 사전 정렬 → peg-in-hole 삽입. 삽입 실패 시 후퇴·재정렬한다.

### 5.2 임무 상태 머신

| 상태 | 동작 | 전이 조건 |
| --- | --- | --- |
| INIT | 씬 로드, 궤도·유영 모션 시작 | 손목캠 토픽 수신 → TRACK |
| TRACK | SAM2(+LLM)로 대상 확정, 파지점 발행 시작 | 파지점 안정 수신 → APPROACH |
| APPROACH | 파지점 실시간 보정 접근 | 오차 허용 범위 진입 → GRASP / 파지점 토픽 끊김 → TRACK |
| GRASP | 그리퍼 폐합, 성공 판정 | 성공 → ATTACH / 실패 → 개방·후퇴 후 APPROACH |
| ATTACH | FixedJoint 생성, 제어 기준 `P`로 전환 | 고정 확인 → ALIGN |
| ALIGN | 도킹점 인식, 사전 정렬 | 정렬 허용 범위 진입 → INSERT |
| INSERT | peg-in-hole 삽입 | 완료 → DONE / 실패 → ALIGN (재시도 초과 시 ABORT) |
| DONE | 도킹 완료, 결과 기록 | — |
| ABORT | 안전 자세로 후퇴, 실패 원인 기록 | 재시도 초과, 비정상 접촉, 토픽 장기 손실 |

## 7. Critical Point 범위 (1차 시연, 9/21)

### 7.1 정의

이 프로젝트에서 가장 어렵고 가장 먼저 증명해야 하는 지점은 **"베이스와 대상이 모두 움직이는 상황에서, 토픽으로 들어오는 파지점을 실시간으로 반영해 실제로 잡는 것"** 이다. 인지(SAM2·LLM)와 도킹(peg-in-hole)은 이 루프가 동작한다는 전제 위에 올라가므로, 1차 시연은 이 구간을 통합 동작으로 보여주는 데 집중하고 나머지는 단독 검증 또는 설계안으로 보여준다.

### 7.2 범위 표

| Flow 구간 | 1차 시연 형태 | 성공 기준 | 막혔을 때 대체안 |
| --- | --- | --- | --- |
| **A1~A5** 환경·에셋·모션 | 🔴 통합 동작 | 커스텀 MEP·위성 USD 로드, MRV 궤도 이동, MEP 떨림이 한 씬에서 동작 | 위성 USD 미완 시 MEP만 로드 |
| **B3~B6** 파지점 발행·실시간 보정 파지 | 🔴 통합 동작 | 유영 중인 MEP를 파지점 토픽 기반으로 1회 이상 파지하는 영상 | 파지점을 GT 스텁으로 발행 (인터페이스 동일) |
| B1 SAM2 세그멘테이션 | 🟠 단독 검증 | 손목캠 프레임에서 MEP 마스크 시각화 | 녹화 프레임으로 오프라인 실행 |
