## 1. 로봇 흔들림 + PhysX error

**증상**
- 아무 명령이 없어도 로봇팔이 흔들리거나 혼자 움직임
- 로그에 `PhysX error: PxArticulationJointReducedCoordinate::setDriveTarget() only supports target angle in range [-2Pi, 2Pi]` 반복

**조사 과정**
| 실험 | 결과 |
|---|---|
| 원래 명령 + 액션 0 | 첫 스텝에 관절 속도 4000 rad/s, 손가락 관절 −411 rad → NaN으로 폭발 |
| 그리퍼를 작은 것으로 바꾸거나 없앰 | 똑같이 폭발 → 그리퍼는 원인 아님 |
| 링크별 접촉력 측정 | 베이스 링크(`canadarm3_large_0`)에 **6.2×10¹⁶ N** |
| 스캐너리(VenusExpress)만 100 m 이동 | 접촉력 0, 관절 속도 0, PhysX 에러 0 |

**원인**
- 3.4배로 키운 VenusExpress(위치 −1.65, 0, −1.05)가 로봇팔 베이스와 겹쳐 있음
- PhysX가 고정된 베이스를 밀어내다 관절이 튕겨 나가고, IK 목표 각도가 24 rad까지 커지면서 ±2π 제한 에러 발생
- Canadarm3 관절은 각도 제한이 없어서(±inf) 목표값이 그대로 커짐

**수정** (`srb/tasks/manipulation/debris_capture/task.py`)
- `filter_robot_scenery_collisions = True` 옵션 추가: 로봇팔과 스캐너리 사이 충돌만 끔 (`UsdPhysics.FilteredPairsAPI`)
- 한계: 팔 링크가 VenusExpress 본체를 통과할 수 있음 (그리퍼·MEP와 스캐너리 간 충돌은 유지)

**검증** (요청 명령과 같은 설정, 150스텝)
- 접촉력 0, 관절 속도 0.000, `setDriveTarget` 에러 0, 기타 PhysX 에러 0

## 2. 첫 번째 충돌 필터 수정이 효과 없음

**증상**: 필터를 넣었는데 접촉력이 6.2×10¹⁶ N 그대로

**원인**
- 로봇 프림에 필터 대상이 `end_effector` 하나뿐이었음 (스캐너리가 안 들어감)
- SRB의 `resolve_env_prim_path` 정규식이 `/World/envs/env_.*`라서 `.*`가 경로 끝까지 삼킴
- `/World/envs/env_.*/robot`이 `/World/envs/env_0`으로 바뀌어, 필터가 로봇이 아니라 env 루트 프림에 붙음

**수정**
- `task.py`에 경로를 문자열로 직접 바꾸는 `_env_prim_path` 함수 추가
- 스캐너리 루트와 모든 충돌 프림을 필터 대상으로 지정

**검증**: 위 1번 검증 결과가 이 수정 이후 결과임

## 3. MEP/위성 충돌 메시 파싱 에러

**증상**: `triangle mesh collision ... cannot be a part of a dynamic body` 에러 약 60개

**원인**: MEP·위성은 움직이는 강체인데 삼각형 메시 충돌을 그대로 사용

**수정**: `task.py`의 MEP·위성에 `MeshCollisionPropertiesCfg(mesh_approximation="convexHull")` 적용

**검증**: 파싱 에러 0개

**남은 우려**: convexHull이 손잡이와 받침 사이 빈틈을 메워 손가락이 감쌀 공간을 줄일 수 있음 (코드 점검에서 지적, 미확인)

## 4. 손목 카메라가 그리퍼 방향을 보지 않음

**증상**: 카메라 위치 (0, 0, −1.1), 방향 (0, 0, −90)을 코드에 넣어도 옆을 봄

**원인**
- Isaac Sim 속성창의 값은 USD 카메라(OpenGL) 규약인데, SRB 설정은 `convention="world"`였음
- world 규약에서 (0,0,−90)은 7번 링크 −Y(옆), OpenGL 규약에서는 −Z(그리퍼 방향)를 봄

**수정** (`task_visual.py`)
- `convention="opengl"`, 위치 (0,0,−1.1), 방향 (0,0,−90)
- 해상도 64×64 → 320×240 (64×64로는 멀리 있는 손잡이 인식 불가)
- 설정 필드: `wrist_camera_pos`, `wrist_camera_rpy`, `wrist_camera_resolution`

**검증**: 카메라 화면에 손가락과 손잡이가 보이고, 노드 계산 결과 그리퍼 기준 카메라 위치 (0,0,−0.66), 광축 −Z

## 6. `No module named 'rclpy'`

**증상**: `srb agent ros` 실행 시 시뮬이 시작 단계에서 멈춤

**원인**
- `srb agent ros`만으로는 ROS 2 브리지가 켜지지 않음 (`--interface ros` 필요)
- 브리지는 실행 **전에** `ROS_DISTRO`, `LD_LIBRARY_PATH`가 설정돼 있어야 함 (`ROS_DISTRO env var not found`)

**해결**
```bash
export ROS_DISTRO=jazzy
export RMW_IMPLEMENTATION=rmw_fastrtps_cpp
export LD_LIBRARY_PATH=/home/rokey/isaac-sim/exts/isaacsim.ros2.bridge/jazzy/lib:$LD_LIBRARY_PATH
srb agent ros --interface ros --env debris_capture_visual ...
```
- 주의: 시뮬 터미널에서 `source /opt/ros/jazzy/setup.bash` 금지 (시스템 ROS는 Python 3.12, Isaac Sim은 3.11)

## 11~12. 탐색 실패 / 탐색이 느림

**1차 문제**: 손목만 좌우 ±90° 돌리는 방식 → 시작 자세가 손잡이 반대편이면 15분 동안 못 찾음

**1차 개선**: 팔 전체가 베이스 축 기준으로 360° 공전하며 탐색
- 결과: 찾기는 성공했지만 약 11분 소요

**2차 문제 (로그 근거)**
- 공전 명령 0.1 rad/s인데 실제 1번 관절은 0.007 rad/s → "팔이 못 따라오면 공전 멈춤" 조건이 93% 시간 동안 걸려 있었음
- 한 바퀴 후 1번 관절 5.39 rad → 같은 방향으로 더 돌면 2π를 넘어 PhysX error 재발 위험

**2차 개선**
- 목표를 실제 팔 방향보다 항상 20° 앞에 둬서 멈추지 않고 계속 회전
- +180°까지 갔다가 −180°로 돌아오는 양방향 탐색 → 1번 관절이 ±2π 안에 머묾
- 오프라인 계산: 느린 팔 기준 약 2분 이내

**2차 개선 검증 (시뮬, 반대편 시작 자세)**
| 항목 | 1차 (공전) | 2차 (양방향 스윕) |
|---|---|---|
| 손잡이 발견까지 | 약 11분 | **약 3.7분** |
| PhysX error | 0 | **0** (1번 관절 ±2π 이내 유지) |
| APPROACH 중 놓침 | 0회 | 13회 (재탐색으로 복구) |

## 13. gripper_fixture 전체를 초록으로 칠한 경우

**증상**: 원통을 찾은 뒤 APPROACH와 SEARCH를 20번 넘게 오가며 FINAL에 못 들어감

**검증**: 되돌린 뒤 APPROACH 중 놓침 0회, FINAL 진입 성공

## 14. 파지 확인

**배경**: 첫 성공 실행에서 HOLD까지 갔지만 손가락 1·2는 도중에 막히고 3은 끝까지 닫힘 → 빗나갔을 가능성

**추가 기능** (`scripts/ros2/mep_handle_grasp.py`)
- `retreat_distance` 파라미터: HOLD 후 그리퍼를 닫은 채 후퇴
- MEP가 따라온 비율이 0.8 초과면 `HELD`, 아니면 `NOT HELD` 로그 출력

**파지 확인 테스트 결과: `NOT HELD`**
| 항목 | 결과 |
|---|---|
| 상태 전환 | SEARCH → APPROACH → FINAL → CLOSE → HOLD → RETREAT → DONE 모두 통과 |
| 추정 위치 | (0.463, 4.699, 5.064), 실제 (0.516, 4.70, 5.086)와 약 5 cm 차이 |
| 손가락 (CLOSE 후) | 6개 모두 1.2 rad = 완전히 닫힘 → **아무것도 잡지 못함** |
| MEP 위치 | x 0.472 → 0.642 (약 17 cm 밀려남, FINAL 전진 중 접촉 추정) |
| 후퇴 | 0.5 m 목표 중 0.128 m만 이동 (90초 시간 초과) |
| 판정 로그 | `follow ratio -3.83 -> SLIPPED / NOT HELD [timeout]` |

**원인 (코드 점검 결과와 일치)**
1. depth는 원통 앞면만 보여서 위치를 카메라 쪽으로 약 6 cm 짧게 추정 (실측 오차와 일치)
2. 잡는 지점 값이 서로 다름 (노드 0.62, 커밋된 코드 0.672, 손가락 끝 약 0.61)
3. 커밋된 코드(`srb/utils/mep.py`)가 IK 제어점을 그리퍼 −Z 0.672 m로 옮겼는데, 노드는 옛 값 0.01을 사용 → 회전 보정 때 팔이 옆으로 밀림
4. FINAL 시작 시 추정 위치를 고정 → 접촉으로 MEP가 밀려도 옛 위치를 향해 닫음

**수정** (`scripts/ros2/mep_handle_grasp.py`)
| # | 수정 | 파라미터 |
|---|---|---|
| 1 | 추정 위치를 시선 방향(원통 축에 수직 성분)으로 πr/4 ≈ 5.9 cm 뒤로 보정. 계산 테스트: 오차 0.0589 m → 0.0000 m | `handle_radius` = 0.075 |
| 2 | 잡는 지점을 손가락 뿌리(0.48)와 끝(0.61) 사이로 설정 (추정값, 조정 가능) | `tcp_offset` 0.62 → **0.55** |
| 3 | IK 제어점을 커밋된 코드와 일치 | `ik_control_point` 0.01 → **0.672** |
| 4 | 고정 시 위치·접근 방향·원통 축을 **MEP 기준 좌표**로 저장하고 매 주기 MEP TF로 갱신 | `mep_frame` |
| 4 | FINAL이 오래 걸리면 APPROACH로 복귀하고 카메라 추정 재개 | `final_timeout` = 240초 |

**상태**: 문법 검사·보정 계산·노드 실행 확인. **시뮬 파지 테스트는 사용자 확인 대기**
